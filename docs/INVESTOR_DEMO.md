# Investor / owner demo — 7 to 10 minutes

## Objective

Demonstrate that this is not two disconnected event apps and not a cosmetic reskin. It is one reusable fashion-event platform with shared identity and infrastructure, while each event retains its own registration, brand experience, programme, permissions, pass and operating control.

## 0:00 — One platform

Open the mobile web app.

Show the persistent MFW / BFS switcher.

Message: one account and one technology platform; each event remains operationally independent.

## 1:00 — MFW

Open MFW Today.

Show runway-led editorial visual language, show programme and buyer role.

Open My Pass and display the MFW BUYER QR.

Message: MFW experience is designed around shows, designers, buyers, showroom and city-facing fashion content.

## 2:30 — Switch to BFS

Tap BFS without logging in again.

The shell changes to the BFS business-summit identity. Show business programme, delegate mode and B2B entry point.

Open My Pass again. The QR is now a different BFS DELEGATE credential.

Message: shared identity does not mean shared access. Registration and credentials are event-bound.

## 4:00 — Combined Today

Return to Today and show the cross-event feed.

Message: during overlapping dates the platform can become the digital layer for Moscow's fashion ecosystem, while preserving the identity of each event.

## 5:00 — Registration model

Open Profile.

Show one global account and two independent event registrations.

Explain that common profile data can prefill an application, but the user explicitly applies to MFW and BFS separately.

## 6:00 — BFS networking

Open BFS Programme / B2B.

Explain delegate/delegation authority, meeting request/acceptance and conflict protection.

## 7:00 — Operations

Open Control.

Switch MFW / BFS while remaining in Control.

Show separate registration/programme/access metrics and event-scope lock.

Message: one operations platform can run both events without cross-event mutations.

## 8:00 — What is already real

- event-aware domain model;
- separate registration authority;
- programme authority;
- BFS delegation and B2B authority;
- signed event-bound QR credentials;
- Combined Today;
- event-scoped admin model;
- PostgreSQL migrations;
- automated isolation tests;
- Render-ready web service.

## Commercial story

Phase 1 is a sellable event MVP, not a throwaway prototype.

The same authority model can later support native iOS, Wallet passes, real accreditation, scanners, push notifications, streaming, sponsor attribution, buyer/brand workflows and additional fashion events without rebuilding identity and access from scratch.
